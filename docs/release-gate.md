# 放行闸门清单

最终放行（`request_release`）不是单个主管点头，而是闸门对案卷证据的逐条核验。
任一条件不满足：拒绝放行、写入 `release_rejected` 签署事件、一次性返回全部缺口。

| # | 检查项 | 通过条件 |
| --- | --- | --- |
| 1 | triaged | 案卷已完成三类成因分诊 |
| 2 | work_order | 存在进行中的检修工单 |
| 3 | required_actions | 方案要求动作全部完成（换件/参数回退/校准/复测） |
| 4 | bypass_lifted | 本案卷旁路全部解除（超时未解除同样阻断） |
| 5 | retest_pass | 复测通过，且记录了基准器具与读数 |
| 6 | params_confirmed | 各控制器当前参数集均为"已确认"（回退即确认） |
| 7 | no_recall_hit | 所有在装部件的型号+批次未命中有效召回 |
| 8 | post_repair_calibration | 每个换件安装位在换件后对新序列号有合格校准 |
| 9 | action_qualifications | 每条签署动作的凭证在动作时刻有效、工具在授权清单内 |
| 10 | reviewer_independent | 放行人未签署过本案卷任何检修动作（职责分离） |

放行人还须具备 `release_reviewer` 角色且复核凭证在有效期内（服务层前置校验）。

## 放行记录回答的四个问题

`release_trace(alarm_id)` 返回：

1. **采用了哪个版本** — 每个控制器的软件版本与参数集版本、确认状态。
2. **谁用什么工具处理了哪个部件** — `actions[]`：动作类型、时间、人员、
   凭证、工具、目标安装位、部件型号/序列号/批次、拆下件序列号。
3. **复核为何同意恢复** — `review_rationale` + 十项闸门检查的逐项证据。
4. **恢复了什么** — `resumed_caps`：模拟放行后重算能力，列出可承担动作。

## 拒绝也是结论

闸门拒绝时系统同样留痕：`release_rejected` 含复核人、复核凭证、
当时全部 gate_checks 与缺口汇总。案卷回到待复测，补正后可再次申请；
放行结论与拒绝历史都不可删除（仅追加日志）。
