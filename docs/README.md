# 港机维护与能力放行产品（PMMS）

面向高度自动化港区的**维护授权与能力放行**系统：从一条报警原文出发，串起设备配置、
部件序列号批次、控制软件与参数、校准记录、检修方案、备件、人员资质和停机窗口，
最终给出可向调度席解释的能力恢复结论。

系统可独立运行（纯 Python 3.11 标准库，无外部服务依赖），所有业务事实以
**签名哈希链事件日志**为唯一来源。

## 解决什么问题

| 现场痛点 | 产品回应 |
| --- | --- |
| 报警后无法先判断机械故障、校准漂移还是未确认软件参数 | 分诊必须三选一并给出依据；方案按成因绑定，错配不能开工 |
| 远程诊断取数范围不清 | 授权会话 + 最小数据范围白名单 + TTL，每次取用留痕，越权即拒 |
| 换件、参数回退、旁路、复测责任不清 | 每类动作独立签署，记录人员、凭证、工具、对象部件，闸门逐条核验 |
| 并行检修互相覆盖 | 工单持有设备/安装位资源锁，锁交集即冲突；不交集的并行作业允许同窗口进行 |
| 离线补录时间造假 | 双时间戳（实际发生 / 系统接收），72 小时补录时限，未来时间直接拒绝 |
| 召回批次命中关联设备 | 在装件实时比对召回清单：装机/预留即拦截，已装机能力立即暂停，ETR 待定 |
| 调度只看到笼统的"维修中" | 输出挂起原因清单、仍可承担动作、预计恢复时间及计算依据 |
| 放行说不清"恢复的是什么" | 放行溯源回答：哪个软件/参数版本、谁用什么工具处理了哪个部件、复核为何同意 |

## 快速开始

```bash
# 端到端业务故事（吊具传感器异常全流程，写入 data/）
python -m pmms.demo

# 调度视图：状态 / 挂起原因 / 可承担动作 / ETR
python -m pmms.cli status

# 报警案卷（含授权取数记录与全部签署动作）
python -m pmms.cli alarm AL-20260922-018

# 最终放行溯源
python -m pmms.cli trace AL-20260922-018

# 哈希链与签名完整性校验
python -m pmms.cli verify
```
