# 自动化港机维护授权

整理自动化港机配置、报警、检修和能力放行资料，定义"由报警原文到最终放行"的独立运行合同。

## 资料范围

领域资料位于 `fixtures/domain.json`，结构约定见 `contracts/domain.schema.json`。当前记录类型包括设备配置、报警事件、诊断会话、检修方案、备件流转、放行结论、部件序列号台账、控制软件参数、校准记录、人员资质、停机窗口、处置签署、召回公告、能力状态；状态示例为 运行中 → 已告警 → 诊断中 → 检修中 → 待复测 →（能力暂停 / 限制运行）→ 已放行。这些样例使用虚构标识，不含真实个人资料、账号或连接凭据。

## 核心规则

1. **报警原文为起点**：PLC 原始报文 `raw_text` 原样保留，诊断会话必须绑定报警编号；维护主管先在机械故障、校准漂移、未经确认的软件参数三类候选原因中定因。
2. **授权会话与最小必要**：远程诊断须在绑定报警、用途和到期时间的会话内取数；允许范围、拒绝范围与会话规则见 `diagnostic_scopes`，会话结束凭据失效。
3. **四类签署**：换件、参数回退、临时旁路、复测各自留痕（`signoff_actions` 定义各自动作必填字段，`sample.signoffs` 给出四条实例）。
4. **并行检修不互相覆盖**：每张工单声明锁定范围（设备/部件/软件参数/校准通道粒度），同一设备并行工单范围不得相交，相交则排队。
5. **离线补录保留实际发生时间**：每条补录同时记录 `occurred_at`（实际发生）与 `recorded_at`（系统登记），时间线以 `occurred_at` 排序，审计同时展示两时间。
6. **召回联动能力暂停**：召回公告按批次（`LOT-xxxx`）匹配部件台账；命中在役设备的相关能力立即转"能力暂停"并刷新调度视图，持续到换件并复测通过。
7. **调度席视图**：返回当前状态、**预计恢复时间**和**仍可承担的动作**（以及暂停动作、放行门槛），不是笼统的"维修中"；召回挂起设备 ETA 为 null。
8. **最终放行五要素**：采用的软件/参数版本、处置人及资质、使用的工具、处理的部件及序列号、复核人同意恢复的理由（`release_elements` / `sample.release`）。

## 样例链路（sample_id 092201-002）

1. 08:14 RMG-03 吊具高度传感器信号跳变 >85mm，远程司机确认告警；
2. 授权诊断会话 DS-0922-17 只读拉取配置/序列号/校准/参数，定因"未经确认的软件参数"为主因（零点参数被改且无签署），机械抖动为表象，校准漂移排除；
3. 停机窗口 WIN-0922-03（09:10–09:55）内两张并行工单：机械组换件（井道无信号，09:32 实际换好、09:47 回室补录）与控制组在线回退参数至 `param-set-19`；
4. 09:12 批准 AI-7 联锁临时旁路（09:50 到期，限远程人工对位着箱）；
5. 10:05 厂商召回 LOT-H2207——旧件已退库的 RMG-03 未被暂停；在役命中的 RMG-05/07 全部能力立即暂停、无 ETA；
6. 10:26 复测两项合格；10:30 复核人确认版本、批次、复测与联锁恢复后放行，回答清"谁用什么工具处理了哪个部件、采用哪个版本以及为何同意恢复"。
